# A2UI Chatbot 연동 POC 개발 계획

작성일: 2026-07-12

## 1. 개발 목적

기존 Chatbot의 Agent 호출 구조를 A2UI Proxy Agent를 경유하는 형태로 변경한다.

```text
Chatbot UI
→ A2UI Proxy Agent
→ Main Agent
→ 데이터 조회
→ A2UI Proxy Agent
→ Chatbot UI
```

사용자가 특정 데이터를 요청하면 Main Agent가 필요한 데이터를 조회하고, A2UI Proxy Agent가 조회 데이터에 적합한 A2UI 템플릿을 판단한다.

Chatbot에는 일반 채팅 답변을 우선 표시하고, 적용 가능한 A2UI 화면이 있으면 Chatbot Renderer를 통해 데이터 화면을 추가로 제공한다. 여러 표시 방식이 가능한 경우에는 사용자에게 목록, 카드, 테이블 등 원하는 표시 방식을 선택하도록 한다.

이번 개발은 운영 시스템 완성이 아닌 POC를 목적으로 하며, 주요 호출 흐름과 A2UI 렌더링 가능성을 검증하는 수준으로 범위를 제한한다.

## 2. 주요 개발 범위

### 2.1 Chatbot Renderer 개발

기존 Chatbot UI에 A2UI 응답을 표시할 수 있는 Renderer를 추가한다.

- 기존 Chatbot 코드 구조 및 Renderer 적용 지점 확인
- A2UI Surface 응답을 처리하는 Renderer 추가
- 일반 채팅 메시지와 A2UI 화면 동시 표시
- 스트림 응답 처리
- 로딩, 빈 데이터 및 오류 상태 처리
- 템플릿 선택 UI 추가
- 사용자가 선택한 템플릿으로 데이터 표시

### 2.2 Chatbot 코드 연동

기존 Chatbot의 Agent 호출 방식을 A2UI Proxy Agent를 통하도록 변경한다.

```text
기존
Chatbot → Main Agent

변경
Chatbot → A2UI Proxy Agent → Main Agent
```

- 기존 Agent 호출 코드 변경
- Proxy Agent URL 및 환경 설정 적용
- 스트림 이벤트 수신 방식 연동
- 텍스트 응답과 A2UI 응답 구분 처리
- 사용자의 템플릿 선택 요청 처리

### 2.3 A2UI Proxy Agent 개발

Chatbot과 Main Agent 사이에서 요청과 응답을 중계하고, 조회 데이터에 적용할 A2UI 화면을 결정하는 Proxy Agent를 개발한다.

- Chatbot 요청 수신
- Main Agent URL 호출
- Main Agent 요청·응답 형식 변환
- Main Agent 스트림 중계
- 조회 결과에서 렌더링 대상 데이터 추출
- 데이터 구조와 등록된 A2UI 템플릿 비교
- 적용 가능한 템플릿 후보 반환
- 사용자가 선택한 템플릿에 맞는 A2UI 응답 생성
- 오류 처리 및 일반 텍스트 fallback 제공

### 2.4 A2UI 템플릿 개발

POC에서 사용할 기본 템플릿 3종을 개발한다. 실제 연동 데이터의 형태에 따라 세부 템플릿 종류는 조정할 수 있다.

1. 데이터 테이블
   - 여러 행과 컬럼으로 구성된 업무 데이터 표시

2. 카드 또는 목록
   - 장비, 자원, 사용자 등의 개별 항목 표시

3. 상세 또는 요약
   - 단일 대상의 주요 정보나 상태 표시

### 2.5 A2UI Admin 개발

A2UI 템플릿을 간단하게 관리할 수 있는 Admin 기능을 개발한다.

- 템플릿 목록 조회
- 템플릿 등록
- 템플릿 수정
- 템플릿 활성화 및 비활성화
- 입력 데이터 스키마 설정
- 데이터 필드 매핑 설정

다음 기능은 POC 범위에서 제외한다.

- 템플릿 미리보기
- 승인 절차
- 템플릿 버전 관리
- 상세 사용자 권한 관리

## 3. 사용자 동작 흐름

사용자가 다음과 같이 데이터를 요청하는 상황을 기준으로 한다.

```text
사용자: 최근 설비 점검 데이터를 보여줘.
```

처리 과정은 다음과 같다.

1. Chatbot이 사용자 요청을 A2UI Proxy Agent에 전달한다.
2. Proxy Agent가 Main Agent를 호출한다.
3. Main Agent가 관련 업무 데이터를 조회한다.
4. 처리 상태와 기본 채팅 답변을 스트림으로 전달한다.
5. Proxy Agent가 조회 데이터와 등록된 템플릿을 비교한다.
6. Chatbot에 일반 채팅 답변을 표시한다.
7. 사용 가능한 화면이 여러 개이면 사용자에게 표시 방식을 묻는다.

```text
어떤 방식으로 보시겠습니까?

[테이블] [카드] [요약]
```

8. 사용자가 선택한 방식으로 A2UI 화면을 표시한다.
9. 적용할 수 있는 템플릿이 없으면 일반 채팅 답변만 표시한다.

## 4. 스트림 이벤트 구성안

Chatbot과 A2UI Proxy Agent 사이에서는 다음과 같은 이벤트를 사용할 수 있다.

| 이벤트 | 용도 |
| --- | --- |
| `state` | 요청 분석, 데이터 조회 등 처리 상태 전달 |
| `text` | 일반 채팅 답변 전달 |
| `display_options` | 사용자가 선택할 수 있는 템플릿 후보 전달 |
| `surface` | 선택된 A2UI 화면 데이터 전달 |
| `error` | 오류 정보 전달 |
| `done` | 현재 응답 처리 종료 |

이벤트 이름과 데이터 구조는 Main Agent 및 기존 Chatbot의 스트림 규격을 확인한 후 최종 확정한다.

## 7. POC 완료 기준

- Chatbot이 A2UI Proxy Agent를 통해 Main Agent를 호출할 수 있다.
- Main Agent의 텍스트 응답을 스트림으로 표시할 수 있다.
- 데이터 조회 결과에 맞는 A2UI 템플릿 후보를 찾을 수 있다.
- 사용자가 원하는 표시 방식을 선택할 수 있다.
- 선택한 A2UI 화면이 Chatbot에 렌더링된다.
- 기본 템플릿 3종이 동작한다.
- Admin에서 템플릿 등록, 수정 및 활성화 상태를 관리할 수 있다.
- 적합한 템플릿이 없는 경우 일반 채팅으로 정상 처리된다.
- 주요 오류 상황에서도 Chatbot 흐름이 중단되지 않는다.

## 8. 요약

4주 동안 다음 순서로 POC를 진행한다.

```text
Proxy Agent 개발
→ Chatbot Renderer 적용
→ 기본 템플릿 3종 및 Admin 개발
→ 사용자 템플릿 선택 기능 적용
→ 전체 연동 및 POC 검증
```

핵심 검증 대상은 Main Agent가 조회한 데이터를 A2UI Proxy Agent가 전달받아 적절한 화면 후보를 제시하고, 사용자가 선택한 화면을 기존 Chatbot 안에서 정상적으로 렌더링할 수 있는지 확인하는 것이다.
